# Changelog

All notable changes to GLYPH are documented in this file. Each language
package (`go/`, `py/`, `js/`) is versioned independently but released in
lockstep from a shared tag, so one entry covers all three unless noted.

Format loosely follows [Keep a Changelog](https://keepachangelog.com/);
versioning follows [SemVer](https://semver.org/) per package
(`glyph-py` on PyPI, `cowrie-glyph` on npm, `github.com/Neumenon/glyph/go`
on the Go module proxy).

This is the first entry in this file — earlier history is in `git log`
(pre-1.1.0 work landed under tag `v1.0.0` and 35 commits since).

## [1.1.0] - 2026-07-02

### Breaking changes

- **Python: struct and sum loose canonicalization now matches the spec and
  the Go/JS reference.** `canonicalize_loose` previously emitted structs as
  `TypeName{...}` and sums as `Tag(value)`; per CANONICAL_FORMS.md (G1/G2)
  Loose collapses a struct to a plain map `{field=val ...}` (sorted keys, no
  TypeName) and a sum to `{tag=value}` (no-payload sums: `{tag=_}`). Go and
  JS already did this; Python silently diverged, which meant Python-computed
  fingerprints of struct/sum values never matched Go/JS.
  **Who this affects:** anyone who persisted Python-computed
  `fingerprint_loose`/patch-base fingerprints of struct or sum values —
  those hashes change (to the values Go/JS always produced). JSON-domain
  values (maps/lists/scalars) are unaffected; all 51 conformance cases are
  byte-identical before and after.
- **`Diff`/`diff` now stamps and enforces the base fingerprint.** Patches
  generated by `Diff(from, to)` (Go), `diff(from_value, to_value)` (Python),
  and `diff(from, to)` (JS) now carry the base fingerprint of `from`, so
  `ApplyPatch`/`apply_patch`/`applyPatch` reject them against any other
  state (previously the generated patch had an empty base and applied to
  anything without error — silently defeating optimistic-concurrency
  protection). **Who this affects:** callers applying diff-generated patches
  to states other than the diff's `from` value; use the unchecked-apply
  opt-out if that is genuinely intended. Emitted patch text now includes an
  `@base=` header.

- **JS: `fromJson` no longer sniffs types by default.** `parseDates` and
  `parseRefs` on `FromJsonOptions` now default to `false` (were `true`).
  Previously, `fromJson` would opportunistically parse ISO date strings as
  `time` values and `^prefix:value` strings as `ref` values; this made its
  output diverge from Go's `FromJSONLoose` and Python's `from_json`, which
  never sniff. The divergence broke fingerprint parity: the same JSON input
  produced different canonical bytes (and therefore a different
  `fingerprintLoose`/`FingerprintLoose`/`fingerprint_loose` hash) depending
  on which language's bridge parsed it — a correctness bug for anything using
  fingerprints as a cross-language identity check.
  **Who this affects:** callers relying on the old default to auto-detect
  dates/refs from plain JSON strings. **Upgrade:** pass
  `{ parseDates: true, parseRefs: true }` explicitly to `fromJson` to keep
  the old sniffing behavior for a JS-only pipeline. `jsonToPacked`,
  `jsonToTabular`, and `jsonToLyph` (the schema-driven emitters) are
  **unaffected** — they still default sniffing to `true`, because
  schema-typed emission expects typed values and was never part of the
  cross-language fingerprint-parity contract.

- **`ApplyPatch`/`apply_patch`/`applyPatch` now verify the patch's base
  fingerprint by default, in all three languages.** A patch that records a
  base fingerprint (via `@base=`, `PatchBuilder.WithBaseValue`, or
  `diff()`'s output) is now checked against the value being patched
  *before* any operation is applied; a mismatch raises a typed error
  (`PatchBaseMismatch` / Go `*FingerprintMismatch`, aliased as
  `PatchBaseMismatch`) instead of silently applying a delta against the
  wrong state. A patch with no recorded base fingerprint still applies
  unconditionally, exactly as before.
  **Who this affects:** callers who called standalone `ApplyPatch` (or
  the equivalent in Python/JS) against a base they had *not* pre-verified,
  relying on the old no-check behavior — e.g. deliberately force-applying a
  patch to a base you know differs from where it was computed. **Upgrade:**
  use the explicit opt-out — Go `ApplyPatchUnchecked(v, p)`, Python
  `apply_patch(v, p, verify_base=False)`, JS
  `applyPatch(v, p, { verifyBase: false })` — to restore the old
  unconditional-apply behavior. Callers who already verified the base
  out-of-band (e.g. the GS1 streaming cursor, which enforced this on-stream
  even before this change) are unaffected either way — the check is
  idempotent.

### Added

- **`Diff()` / `diff()` ported to Python and JS**, matching Go's existing
  `Diff(from, to, typeName)`. Computes a `Patch` between two values with
  matching whole-list-replace semantics (list diffing is not
  element-wise) across all three languages. Useful as the producer side of
  the base-fingerprint-enforced `ApplyPatch` above: `diff()`'s output always
  carries a base fingerprint computed from `from`.
- **Python: full GS1 stream protocol** (`glyph.stream` — `Writer`, `Reader`,
  `StreamCursor`, `crc`, `hash`/`state_hash_loose`, `ui_events`, `gs1t`
  frame types), bringing Python to parity with Go and JS for stream framing.
  Previously Python had no GS1 implementation at all.
- Go and Python: doc-comment disambiguation between `FingerprintLoose` /
  `fingerprint_loose` (64-hex, no-tabular canonical form, value-identity
  digest) and a patch's base fingerprint (16-hex, with-tabular canonical
  form, enforced apply-time precondition) — these are easy to confuse and
  are not interchangeable. JS gained the equivalent note on
  `fingerprintLoose`.
- JS: package root (`js/src/index.ts`) now exports `diff`, `verifyPatchBase`,
  `computeBaseFingerprint`, `PatchBaseMismatch`, and `ApplyPatchOptions` —
  these existed internally but were not reachable from `import { ... } from
  'cowrie-glyph'`, making the ported `diff`/base-verification APIs
  unusable by normal consumers. Python's `__init__.py` already exported the
  equivalent set.

### Fixed

- **Python GS1 UI events now emit the typed struct form, matching Go's
  `EmitUI` bytes.** `emit_ui` previously used `canonicalize_loose`, which
  (post-canonicalization-fix) collapses the event struct to a map and broke
  `parse_ui_event` round-trip and Go wire parity; it now emits
  `TypeName{...}` exactly as Go does.
- **Go module is now `go get`-able.** The module lived in subdirectory
  `go/` while declaring its path as `github.com/Neumenon/glyph` (missing the
  `/go` suffix), so an external `go get github.com/Neumenon/glyph/go@latest`
  found no `go.mod` at the expected path and failed. The module path is now
  `github.com/Neumenon/glyph/go`, matching the monorepo-subdirectory
  convention `go get` expects.
- The Go module's dev-only `cogs`-build-tagged cowrie bridge
  (`go/glyph/bridge.go`, `bridge_collision_test.go`, `cmd/bridgecheck`) —
  which imported the unpublished `github.com/Neumenon/cowrie` and kept it
  in `go.mod`/`go.sum` — has been removed. `go.mod` is now
  dependency-free; `go mod tidy` is a no-op.
- `attic/rust/glyph-codec/README.md`: the install snippet (`glyph-rs =
  "1.0"`) implied a published crate. The crate has `publish = false` and
  has never shipped to crates.io. Replaced with an honest "not published"
  note plus two working alternatives: build/test in place, or a local path
  dependency for anyone wiring it into another crate in this repo.
- `attic/c/glyph-codec/README.md`: documented that `glyph_fingerprint_loose`
  is a plain alias for `glyph_canonicalize_loose` (it returns canonical
  GLYPH text, not a hash) and that the real hash, `glyph_hash_loose`, hashes
  the *with-tabular* canonical form and truncates to 16 hex chars — doubly
  incompatible with Go/Python/JS `fingerprint_loose`/`FingerprintLoose`
  (no-tabular form, full 64-hex digest). Strengthened the top-of-file PARKED
  banner to state explicitly that this port does not participate in
  cross-language conformance testing.
- Root `README.md` rewritten: leads with the verified
  same-value-same-bytes-same-hash property across Go/Python/JS, positions
  GLYPH as a content-addressed identity/verification layer rather than a
  compression format, and replaces prior blanket token-savings claims with
  measured, shape-dependent numbers (~40% homogeneous records, ~25%
  structured traces, ~1-2% nested chat-message state, with an explicit note
  that savings can go negative on prose-heavy payloads). Every code example
  in the new README was executed, not hand-derived, in the language(s)
  claimed.
- Numerous doc-only fixes across `docs/GUIDE.md`, `docs/COOKBOOK.md`,
  `docs/GS1_SPEC.md`, `docs/LOOSE_MODE_SPEC.md`, `docs/GLYPH_FILE_FORMAT.md`,
  and `docs/SPECIFICATIONS.md`: stale/invalid example syntax that no longer
  parses (e.g. `set .foo 42` instead of `= .foo 42`; `Type@(field "value"
  ...)` colliding with the real packed/positional `@(...)` syntax), missing
  `rows=N cols=N` tabular header metadata in example output, and the same
  fingerprint/base-fingerprint conflation called out above. See git history
  on those files for the full per-file breakdown.

### Known documentation gaps (not fixed in this release — flagged for follow-up)

`py/README.md`, `js/README.md`, `docs/GS1_SPEC.md`, and
`docs/API_REFERENCE.md` each still state that GS1 stream framing is
"Go and JS only" / "Python does not implement GS1." This is now stale as of
the GS1 Python addition above; those four files are outside this release's
file-ownership scope and should be corrected in a follow-up pass before or
shortly after publishing.
